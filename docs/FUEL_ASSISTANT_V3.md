# Fuel Assistant V3

## Scope and profiles

The academic profile reads the published ForceGT snapshot for HPCL, IndianOil, BPCL, Jio-bp, Nayara and Shell. It accepts positive INR prices attached to the original outlet ID and product with a capture timestamp. It also searches OpenStreetMap's Asia extract through the public [Dresel Overpass instance](https://ovp.dresel.systems/) for local searches through 10 km. Geoapify is optional. Without a key the 25 and 50 km views use the outlet catalogue. When the supplemental provider fails, the app retains catalogue results and labels partial coverage. The public release profile keeps the outlet catalogue disabled.

| Source | Scope |
| --- | --- |
| ForceGT snapshot | Public, MIT-licensed publisher distribution. The academic app reads its bounded regional shards from GitHub. No direct requests to original retailer feeds. [Dataset and provenance](https://github.com/ForceGT/india-fuel-pumps#provenance--license) |
| HPCL, IndianOil and Nayara | Their consumer locator feeds supply the published snapshot's observations. Original links and crawler timestamps are retained. The site policy and locator terms are separate from the snapshot license. |
| BPCL and Jio-bp | ForceGT attributes the records to its upstream collection from consumer services. DriveSentry uses the published snapshot only. Upstream rates may be absent, stale or inaccurate. |
| Shell | Location and product records can be shown. Missing numeric prices remain unavailable. |
| OpenStreetMap | Independent community locations and geometry. No numeric prices are imported from OSM. [License](https://www.openstreetmap.org/copyright) |

Confirmed, unambiguous same-brand catalogue coordinates inside an appropriate mapped footprint share a single pin. Two distinct catalogue identities or conflicting outlet labels remain separate. Numeric observations stay attached to their original catalogue ID. A premium product name alone does not prove E0.

**Explore India** offers explicit city centres, including Pune and Mysuru, alongside address search where configured. A user can also move the map and search its centre along a trip. Searches remain bounded to the selected 3, 5, 10, 25 or 50 km range. City references show official PPAC-backed values for the four supported metros. Other cities link to nearby dated outlet observations rather than displaying a citywide value. E0 Explorer uses the existing verified-evidence threshold.

The publisher's MIT license covers its contribution to the dataset. The separate retailer feed rights are not established for general redistribution or a production app. The build profile does not make that upstream rights question disappear. Do not distribute the academic APK beyond the reviewed college demonstration without resolving those rights. Original product names, crawler capture times, retrieval times, official source links, and station identities remain on observations. Petrol, diesel and premium classes are separate; neither a brand nor an unlabeled product is evidence of E0.

## Map and location

The Android APK contains Leaflet JavaScript and CSS inside the release bundle, displayed in `react-native-webview`. It uses no Google Maps SDK key. The visible basemap requests HTTPS tiles from `tile.openstreetmap.org`, shows OpenStreetMap attribution, retains normal WebView HTTP caching and does not prefetch bulk tiles. The [tile usage policy](https://operations.osmfoundation.org/policies/tiles/) applies. This public service is best-effort for a small college demo; a production or substantial audience needs a suitable tile provider. Cached outlet and price records are available offline through the existing SQLite station cache, but offline basemap tiles are not guaranteed. The map groups nearby markers, supports pan/zoom and recenter, and shares selected outlets with List. Directions launch an external app using destination coordinates.

Startup requests foreground GPS and marks simulated emulator coordinates. The app has no city preset or silent fallback location. Explicit Indian address searches use a configured Geoapify geocoder or an explicitly configured academic geocoder endpoint. The public Nominatim service is not a default: its [usage policy](https://operations.osmfoundation.org/policies/nominatim/) requires a deployed app to be able to switch that service without an app update. Without a configured geocoder, My Location and a deliberate map-center search remain available. The selected address remains a session preference until My Location reacquires a device fix. Exact radius filtering applies after the rounded cache-area request.

## Build and launch

Use `scripts/Build-CollegeDemo.ps1 -TestingKeystorePath <existing-compatible-keystore>` on a machine with Android Studio SDK, CMake 3.30.5, JBR Java and pnpm. The script creates an isolated run under `.local/build/`. An optional `-BuildRoot` must point to an empty child directory there. It maps a free temporary drive letter for the build, archives the committed revision, uses a build-local hoisted pnpm layout and a per-run pnpm store, and keeps the existing three native package junctions and CMake options. The mapping is released in cleanup. Build files remain in the run directory for diagnosis. To inspect its junctions again, remap that run to the original letter shown in the build output. A successful build copies the signed APK to `.expo/college-demo/DriveSentry-College-Demo-v3.apk`. Check its signer against the installed app before `adb install -r`. Keep DriveSentry scratch files and artifacts inside the assigned workspace. Full Gradle assembly with this workspace-local path is pending.

`scripts/College-Demo.ps1 -Standalone` launches the installed `com.drivesentry.testing` version 3.0.0 without Metro or Expo Go. Optional emulator GPS parameters set a reproducible simulated fix before launch. The normal launcher remains available for Expo development and authorized physical-device GPS checks.

For a presentation on Windows, run `scripts/College-Demo.ps1 -UseWindowsLocation` to load a fresh Windows location estimate into the Android emulator and open Fuel Map in Expo Go. Windows Location services and desktop app access must be enabled. The launcher leaves the emulator location unchanged if Windows cannot supply a fresh estimate within 500 m of reported accuracy. The map labels the estimate as simulated. **Use current location** returns to that point after exploring another area. Rerun the launcher to sync again after moving the laptop. A GPS-capable phone can provide a live device fix directly.

## Nationwide explorer

The search dialog submits queries to a bundled SQLite gazetteer before using any configured address geocoder. The [GeoNames extracts](../THIRD_PARTY_NOTICES.md#geonames-india-gazetteer) contain 565,743 place and administrative records and 155,570 postal locality records, including alternate spellings. PIN matches identify postal localities. Gazetteer results supply a representative coordinate and do not locate a particular house. A configured address provider can search addresses outside the index. An unmatched query never moves the map by itself. The 39.6 MB index is separate from the garage database and has its own versioned, locally imported filename.

The India overview uses ForceGT manifest counts to shade coarse regions in the academic profile. Its total counts published source records, while a local result count reflects the selected search circle after validation and identity matching. Pan or zoom first, then choose **Search this area** to load outlets around the view centre. The catalogue reads only intersecting geohash shards in bounded pages, caches recent versions in memory, and retains incomplete results with a coverage label. A partial refresh does not replace a previously complete SQLite result. Keyless release builds use OpenStreetMap for local searches up to 10 km. The academic build retains its existing ForceGT provenance and wider radius options.

Fountain Circle had six source records for two forecourts. IndianOil listing 197313 and OSM node 3380635539 both fall inside OSM way 623813382. BPCL listing 0000112515 and OSM node 3380635540 both fall inside OSM way 623813381. Each match requires a single catalogue listing, a single compatible mapped node of the same brand, and unambiguous containment. The two catalogue IDs and coordinates remain distinct. Leaflet.markercluster groups dense pins by screen distance and lets users spread them apart at street zoom. Selecting a station pans inside the visible map without changing its zoom. Selecting from a large cluster exposes one pin and updates the badge for the remaining markers. The OpenStreetMap raster basemap can also display small built-in pump symbols.

The keyless Expo Go verification on Android API 37 used the gazetteer results as the centres of 5 km searches. The displayed counts were 119 for Mysuru, 148 for Bengaluru, 84 for Delhi, 94 for Mumbai, 93 for Pune, 169 for Hyderabad and 5 for Melukote. The earlier simulated Mysuru GPS centre showed 108. Counts can differ between centres within the same city. Map/List selection opened a station in each area, and Google Maps received that station's destination coordinates. Revisiting five city searches used their respective saved results. The academic country overview showed 103,914 published records across 197 source cells.

To regenerate the GeoNames asset, extract `IN.txt` from each of the two archives linked in the notices and run `node scripts/build-india-gazetteer.mjs <places.txt> <postal.txt> assets/india-places.db`. Update the local import filename when refreshing the asset. The source archive SHA-256 values for this snapshot are `F1CE814C1841D5E3A57C7F89C5DF294D793B6E1A0ADCBE7B34C72CB325378725` (places) and `014D47A18BE8582508A162F5C4805899DE06310DD24B88A4D49F68482B3806A5` (postal).
